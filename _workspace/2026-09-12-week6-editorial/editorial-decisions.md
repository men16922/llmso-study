# 6주차 아티클 편집 기준

- 사용자 참고 글: https://app.notion.com/p/3c44c2420ac48157aaebe78f971e05c9
- 참고한 형식: 핵심 결과 선제시, 번호가 있는 발견 중심 본문, 비교표 뒤 해석, 실험 조건·부록 접기, 마지막 운영 판단.
- 중심 질문: 정상 응답과 낮은 CPU 사용량만으로 LLM 서빙 용량을 판단할 수 있는가.
- 원문 계정·권한·CLB·배포 문제의 진행 기록은 labs/eks-trainium-workshop/execution-record.md로 이동. 측정 JSON과 실제 화면은 보존.
- 본문에는 출력 길이 × 동시 요청 3회 반복, 지속 부하, CPU HPA 미반응, CPU 합성 부하에서 실제 용량 미증가를 연결.
- 인간화 스킬은 구조를 다시 쓴 4,863자 본문 초안에 한정 적용. 사용자 요청의 구조 개편·생략을 순수 윤문 변경률로 평가하지 않음.
- 추가 승인 후 C4·256토큰·320건을 측정해 지속 부하에서의 동시 요청 감소 효과를 확인 중. 도착률 제어·요청 거절·외부 대기열 정책과 구별.
